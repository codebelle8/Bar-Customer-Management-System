# HARNES TOKYO 会員・来店受付・売上管理システム（MVP）

会員制バー「ハーネス東京」向けの店舗管理システムです（新店舗は別の屋号で追加予定）。
紙の会員規約・Excel（年.月総括シート）での運用を大きく変えずに、会員登録・来店受付・売上集計をシステム化します。

> 本リポジトリの内容（ロゴ・会員規約・売上データ）は機密情報です。外部への公開・共有はしないでください。

## MVP の範囲

| 機能 | 内容 |
| --- | --- |
| ログイン・権限 | オーナー（全店舗）／店舗オーナー（所属店舗の全機能）／スタッフ（所属店舗の受付・会員・売上）。店舗オーナー・スタッフは所属店舗のみ（データベース側でも制御） |
| ダッシュボード | 本日の来店数・売上・ドリンク・経費・現金残高（オーナーのみ）、直近7日の売上推移、料金カレンダー、最近の来店履歴、リピーター特典の対象数 |
| 来店受付 | 新規入会（規約の説明・内容確認→本人確認書類2点の確認→会員情報→お会計）、既存会員の受付（番号・ハンドルネーム検索、出入禁止・重複入店のブロック、リピーター割引の自動適用）、ドリンク注文、退店・追加精算（延長料金の自動計算・ドリンク）、受付の取消、自動退店（退店処理がないまま営業日の区切りを過ぎた来店を区切りの時刻で退店にする。延長料金などは加算しない） |
| 会員管理 | 検索（番号・ハンドルネーム・フリガナ・本名）・一覧・詳細・来店履歴・編集・出入禁止、紙の会員証からの移行登録、Excel 取込（店舗の会員名簿の形式に対応：シートの選択、列の一括対応付け、出禁の印、空き番号の除外、ありえない日付のチェックと一覧の Excel 保存。会員番号が同じでもハンドルネームが違えば別の会員として取り込む（同じ番号・同じ名前は取込済みとして除外）。保険証の番号の列と、備考の8桁以上の番号は取り込まない） |
| 売上管理 | 日報（Excel と同じ列構成）、経費・税金・アルバイト代の入力 |
| レジ金 | 店舗の「レジ金引継ぎシート」と同じ確認項目（開店時・昼の部→夜の部の引継ぎ・締めのレジ金／来店履歴／ギフトカード）を、営業日ごとに確認した人と時刻で記録、引継ぎメモ、月の一覧（未確認の表示） |
| 勤怠 | 社員・アルバイト（アルバイトは名前順）を選んで出勤・退勤を記録（共用のスタッフアカウントで利用可）、月別の出勤日数・勤務時間の集計（給与計算の基礎）、記録の修正・追加、Excel 出力、対象者の登録 |
| レポート | 総括（Excel と同じ計算）、月次推移、会員別売上、料金区分別の内訳、来店者内訳（日別・昼部／夜部 × 男女 × 既存／新規。店舗の「来店者内訳」と同じ並び）、Excel 出力（総括・来店明細・来店者内訳） |
| 料金設定・カレンダー | 昼の部／夜の部 × 平日／週末／祝日／イベント × 男性／女性／カップルの料金表、日付ごとのイベント・個別料金、営業時間、延長料金のルール（1時間ごとに加算する曜日・1時間あたり・上限。対象外の曜日と祝日は夜の部の料金）、ドリンクメニュー |
| 割引・特典 | 前月◯回以上来店の男性は翌月の入場料から割引（回数・金額・対象・毎回／月1回を設定可） |
| スタッフ管理・設定 | アカウント発行・店舗割当・パスワード再発行、店舗情報、入会金・年会費、会員規約の編集 |
| 画面の明るさ | ライト（既定）／ダーク／端末の設定に合わせる。画面右上のボタンで切り替え（印刷は常にライト） |

MVP の範囲は契約書の開発範囲（会員管理／既存会員名簿の移行／受付・会計／料金・割引／売上管理／店舗・スタッフ管理／会員規約／身分証の確認）に合わせています。範囲外の機能は追加しません。
契約書の開発範囲で対象外：誕生日・記念日の通知、ポイント管理

## 技術構成

- **Next.js 16**（App Router / Server Components / Server Actions）＋ TypeScript ＋ Tailwind CSS v4
- **PostgreSQL**（本番：Supabase 東京リージョン、開発：組み込みの PGlite）＋ Drizzle ORM
- **権限制御**：アプリ側のチェックに加え、PostgreSQL の Row Level Security で店舗ごとにデータを分離
  - リクエストごとにトランザクション内で `app_user` ロールに切り替え、`app.role` / `app.store_id` を設定
  - 店舗オーナー・スタッフは他店舗の行を参照・変更できない／料金表・カレンダー・メニューはオーナー（店舗オーナーは自店舗のみ）が変更可／操作の記録（画面なし）はオーナー（店舗オーナーは自店舗のみ）のみ参照可／店舗オーナーが追加・変更できるアカウントは自店舗のスタッフのみ
  - `npm run verify:rls` で検証できます（一時 DB を作成して 27 項目を確認）
- **認証**：パスワードは bcrypt でハッシュ化、セッションは署名付き Cookie（HttpOnly・14時間）
- 日付・時刻はすべて日本時間。営業日は「区切り時刻（初期値 6:00）より前は前日扱い」

```
src/
  app/(app)/        ログイン後の各画面（dashboard, reception, members, sales, cash, attendance, reports, pricing, discounts, staff, settings, terms）
  app/print/terms   会員規約の印刷用紙（A4）
  app/api/export    Excel 出力
  db/migrations     SQL マイグレーション（起動時に自動適用）
  db/schema.ts      テーブル定義（型付きクエリ用）
  db/seed.ts        初期データ（demo / clean）
  lib/dal.ts        ログイン確認・権限・店舗の決定・RLS 付きクエリ
  lib/pricing.ts    営業日・昼夜・料金区分・割引の判定
  lib/stats.ts      日報・総括の集計（Excel と同じ計算）
  lib/attendance.ts 勤怠の勤務時間・並び順（社員→アルバイトは名前順）
  lib/cash.ts       レジ金の確認項目（レジ金引継ぎシートと同じ）
```

## 開発環境

```bash
npm install
cp .env.example .env.local   # SESSION_SECRET を変更
npm run dev                  # http://localhost:3000
```

初回アクセス時に `./.data/pglite` へデータベースを作成し、デモデータ（会員約330名・2026年10月は店舗の Excel 実績を再現・11月は合成データ）を投入します。

| アカウント | パスワード | 権限 |
| --- | --- | --- |
| owner | owner1234 | オーナー（全店舗） |
| harnes-owner | owner1234 | 店舗オーナー（ハーネスのみ） |
| harnes-staff | staff1234 | ハーネスのスタッフ（共用） |
| new01 | staff1234 | 新店スタッフ |

| コマンド | 内容 |
| --- | --- |
| `npm run db:reset` | 開発用 DB を削除（次回起動時に再作成） |
| `npm run verify:rls` | データベース側の権限制御を検証 |
| `npm run typecheck` | 型チェック |
| `npm run build` | 本番ビルド |

## 本番環境（想定）

- アプリ：Vercel（東京リージョン `hnd1`、`vercel.json` で指定済み）
- データベース：Supabase（東京リージョン `ap-northeast-1`）
- 開発用の組み込み DB（PGlite）はサーバーレス環境では使えないため、本番では `DATABASE_URL` が必須です

環境変数：

| 変数 | 内容 |
| --- | --- |
| `SESSION_SECRET` | 32文字以上のランダムな文字列（必須） |
| `DATABASE_URL` | Supabase の **Transaction pooler** 接続文字列（ポート 6543） |
| `SEED_MODE` | 省略時は `clean`（店舗・料金表・初期オーナーのみ）。デモデータを入れる場合のみ `demo` |
| `INITIAL_OWNER_PASSWORD` | 初期オーナーのパスワード（省略時はランダム生成してログに出力） |
| `SITE_PASSWORD` | 確認用の公開環境のみ。設定すると全ページの前に閲覧用パスワードを求める（本番では設定しない） |

初回デプロイ後、オーナーでログインして「スタッフ管理」でスタッフのアカウントを発行し、「料金設定・カレンダー」で正式な料金表を設定してください。
